# RPA自动化程序代码拆解分析与项目重组方案

## 一、现有代码库分析

### 1.1 代码功能映射表

| 文件路径 | 功能描述 | 依赖关系 | 复用潜力 | 标记 |
|---------|---------|---------|---------|------|
| **utils/GUIUtils.py** | 图像识别点击、等待元素、截图等GUI操作 | pyautogui, PIL, pyperclip | **高** - 通用GUI操作 | 保留 |
| **utils/OSUtils.py** | 进程管理(杀进程)、时间转换 | os | **高** - 通用系统操作 | 保留 |
| **utils/NetUtills.py** | 网络检测、端口扫描、Ping功能 | socket, ping3 | **高** - 通用网络操作 | 保留 |
| **utils/SreenRecord.py** | 屏幕录制功能 | cv2, PIL, numpy | **高** - 通用监控功能 | 保留 |
| **utils/Wechat.py** | 企业微信消息发送、文件上传 | requests, pandas | **高** - 通用通知功能 | 保留 |
| **utils/SendMails.py** | 邮件发送功能 | smtplib | **高** - 通用通知功能 | 保留 |
| **utils/ScheduleUtils.py** | Windows计划任务控制 | win32com | **高** - 通用调度功能 | 保留 |
| **utils/ProcessCheck.py** | 进程状态监控 | os | **中** - 可抽象为通用监控 | 保留 |
| **config/appConfig.py** | 配置常量定义 | 无 | **高** - 需重构为配置文件 | 保留优化 |
| **config/ImgConfig.py** | 图像路径配置 | 无 | **低** - 特定软件硬编码 | 需重构 |
| **controllers/ExcuteAlpha.py** | 特定软件操作逻辑 | GUIUtils, ImgConfig | **低** - 强耦合特定软件 | 废弃/重构为Skill |
| **controllers/webOp.py** | 特定Web系统操作 | selenium, GUIUtils | **低** - 强耦合特定Web系统 | 废弃/重构为Skill |
| **controllers/OutBoundList.py** | Excel文件处理逻辑 | pandas, os | **中** - 可抽象为数据处理模块 | 保留优化 |
| **OutBoundFixAssemble.py** | 主业务流程编排 | 所有模块 | **低** - 强耦合特定业务 | 废弃/重构为Agent |
| **main.py** | 程序入口 | 多进程管理 | **中** - 可抽象为启动器 | 保留优化 |

## 三、模块设计方案

### 3.1 基础功能模块

#### 3.1.1 GUI操作模块 (gui_ops.py)

**功能职责：**
- 提供统一的GUI操作接口
- 封装图像识别与点击操作
- 支持键盘输入与快捷键操作
- 提供元素等待与超时机制

**核心接口设计：**

| 接口名称 | 功能描述 | 参数 | 返回值 |
|---------|---------|------|--------|
| click_by_image | 通过图像识别点击 | image_path, offset, confidence | bool |
| wait_until_show | 等待图像出现 | image_path, timeout | Position |
| wait_until_disappear | 等待图像消失 | image_path, timeout | bool |
| type_text | 输入文本 | text, use_clipboard | None |
| press_key | 按键操作 | key, presses | None |
| hotkey | 快捷键操作 | *keys | None |
| take_screenshot | 截图 | save_path | Image |

**设计要点：**
- 采用面向对象封装，提高可测试性
- 支持回调机制，便于错误处理时截图
- 配置化的默认超时时间和置信度

#### 3.1.2 系统交互模块 (os_ops.py)

**功能职责：**
- 进程管理（启动、终止、查询）
- 进程状态监控
- 系统资源信息获取

**核心接口设计：**

| 接口名称 | 功能描述 | 参数 | 返回值 |
|---------|---------|------|--------|
| kill_process | 终止进程 | process_name | bool |
| kill_processes | 批量终止进程 | process_names | dict |
| start_program | 启动程序 | program_path | bool |
| check_process_status | 检查进程状态 | process_name | ProcessInfo |

#### 3.1.3 网络工具模块 (net_ops.py)

**功能职责：**
- 网络连通性检测
- 端口扫描与管理
- 网络监控

**核心接口设计：**

| 接口名称 | 功能描述 | 参数 | 返回值 |
|---------|---------|------|--------|
| is_port_in_use | 检测端口占用 | port, host | bool |
| find_available_port | 查找可用端口 | start, end | int |
| ping | 网络连通检测 | host, timeout | bool |

#### 3.1.4 数据处理模块 (data_ops.py)

**功能职责：**
- Excel文件读写
- 数据过滤与转换
- 文件管理与归档

**核心接口设计：**

| 接口名称 | 功能描述 | 参数 | 返回值 |
|---------|---------|------|--------|
| read_excel | 读取Excel | file_path, **kwargs | DataFrame |
| save_excel | 保存Excel | df, file_path | None |
| filter_by_time_range | 时间范围过滤 | df, column, start, end | DataFrame |
| merge_dataframes | 数据合并 | left, right, on | DataFrame |

### 3.2 大模型调用模块

#### 3.2.1 模块架构

```
LLM模块
├── base.py          # 抽象基类，定义统一接口
├── openai_llm.py    # OpenAI实现
├── zhipu_llm.py     # 智谱GLM实现
├── ollama_llm.py    # Ollama本地实现
└── factory.py       # 工厂类，统一创建入口
```

#### 3.2.2 核心接口设计

| 接口名称 | 功能描述 | 参数 | 返回值 |
|---------|---------|------|--------|
| chat | 同步对话 | messages, **kwargs | LLMResponse |
| chat_stream | 流式对话 | messages, **kwargs | AsyncIterator |

#### 3.2.3 支持的模型提供商

| 提供商 | 模型示例 | 特点 |
|-------|---------|------|

#### 3.2.4 设计要点

- 采用工厂模式统一创建不同提供商实例
- 支持同步和流式两种调用方式
- 配置化管理API密钥和模型参数

### 3.3 Agent模块

#### 3.3.1 模块架构

```
Agent模块
├── agent.py              # 核心Agent类
├── task_planner.py       # 任务规划器
├── resource_scheduler.py # 资源调度器
└── exception_handler.py  # 异常处理器
```

#### 3.3.2 任务规划器 (TaskPlanner)

**功能职责：**
- 解析用户请求
- 生成任务执行计划
- 确定任务依赖关系

**工作流程：**
1. 接收用户自然语言请求
2. 调用大模型分析意图
3. 匹配可用技能
4. 生成任务列表和依赖关系图

#### 3.3.3 资源调度器 (ResourceScheduler)

**功能职责：**
- 管理并发任务执行
- 分配系统资源
- 控制任务优先级

**设计要点：**
- 基于线程池实现并发执行
- 支持任务优先级队列
- 提供任务状态跟踪

#### 3.3.4 异常处理器 (ExceptionHandler)

**功能职责：**
- 捕获并记录异常
- 分析错误原因
- 提供恢复建议
- 触发报警通知

**处理流程：**
1. 捕获异常信息
2. 调用大模型分析原因
3. 生成恢复建议
4. 触发配置的报警回调

#### 3.3.5 Agent核心类工作流程

```
用户请求 → 任务规划 → 资源调度 → 技能执行 → 结果汇总
                ↓           ↓
            异常处理 ← 执行监控
```

### 3.4 Skill模块

#### 3.4.1 模块架构

```
Skill模块
├── base_skill.py    # 技能基类
├── skill_loader.py  # 技能加载器
├── registry.py      # 技能注册表
└── skills/          # 具体技能实现
    ├── desktop_skill.py     # 桌面软件技能
    ├── web_skill.py         # Web操作技能
    ├── excel_skill.py       # Excel处理技能
    └── notification_skill.py # 通知技能
```

#### 3.4.2 技能基类设计

**核心属性：**
- metadata: 技能元数据（名称、版本、描述、分类）
- config: 技能配置

**核心接口：**
- execute(params): 执行技能
- validate_params(params): 验证参数

#### 3.4.3 技能分类

| 分类 | 功能描述 | 示例技能 |
|-----|---------|---------|
| GUI | 桌面软件操作 | 软件登录、菜单操作、数据录入 |
| Web | Web系统操作 | 页面导航、表单填写、数据抓取 |
| Data | 数据处理 | Excel读写、数据转换、文件管理 |
| Notification | 通知发送 | 企业微信、邮件、钉钉 |
| System | 系统操作 | 进程管理、计划任务 |

#### 3.4.4 技能加载机制

**动态加载流程：**
1. 扫描skills目录下的技能文件
2. 通过反射机制加载技能类
3. 注册到技能注册表
4. 根据配置文件初始化技能实例

**配置驱动：**
- 通过YAML配置文件定义技能参数
- 支持环境变量替换
- 支持配置热更新

#### 3.4.5 技能扩展方式

1. **创建技能文件**：在skills目录下创建新技能文件
2. **继承基类**：继承BaseSkill并实现execute方法
3. **添加元数据**：定义技能的名称、版本、参数模式
4. **配置注册**：在配置文件中添加技能配置
5. **自动加载**：系统启动时自动加载新技能
