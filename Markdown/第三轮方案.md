# RPA自动化平台功能泛化设计方案（第三轮）

## 一、功能泛化的核心理念

### 1.1 什么是功能泛化

**功能泛化**是指将针对特定软件、特定场景的硬编码功能，抽象为通用的、可配置的能力模块。通过配置驱动而非代码修改来适配不同的软件和业务场景。

**泛化前（现有代码问题）：**
```
问题：操作逻辑硬编码在代码中
例如：ExcuteAlpha.py 中写死了ALPHA软件的操作步骤
结果：要操作其他软件需要重写代码
```

**泛化后（目标架构）：**
```
解决：将操作抽象为通用能力
例如：桌面软件操作能力 = 图像识别 + 点击 + 输入
结果：通过配置文件描述操作步骤，无需修改代码
```

### 1.2 泛化的三个层次

| 层次 | 泛化内容 | 实现方式 | 效果 |
|-----|---------|---------|------|
| **操作层泛化** | 将具体操作抽象为原子能力 | 基础功能模块 | 点击、输入、等待等能力可复用 |
| **流程层泛化** | 将业务流程抽象为可配置步骤 | Skill + 配置文件 | 新流程只需配置，无需编码 |
| **决策层泛化** | 将人工决策抽象为智能判断 | Agent + LLM | 系统自主处理异常和变化 |

## 二、操作层泛化详细设计

### 2.1 原子操作能力抽象

将所有GUI和系统操作抽象为以下原子能力：

#### 2.1.1 视觉感知能力

**能力描述：** 通过图像识别感知屏幕内容

**泛化设计：**

```
视觉感知能力
├── 图像定位能力
│   ├── 输入：目标图像路径
│   ├── 输出：屏幕坐标位置
│   └── 参数：置信度、超时时间、搜索区域
│
├── 文字识别能力（OCR）
│   ├── 输入：屏幕区域
│   ├── 输出：识别的文字内容
│   └── 参数：语言、识别精度
│
└── 状态检测能力
    ├── 输入：检测规则
    ├── 输出：当前状态（存在/不存在/变化）
    └── 参数：检测间隔、持续时间
```

**配置化示例：**

```yaml
visual_capability:
  image_location:
    default_confidence: 0.8
    default_timeout: 30
    search_regions:
      full_screen: null
      top_half: [0, 0, 1920, 540]
      bottom_half: [0, 540, 1920, 540]
  
  ocr:
    engine: "tesseract"
    language: "chi_sim+eng"
    
  state_detection:
    check_interval: 0.5
    max_wait: 60
```

```
│   └── 等待窗口出现
│
├── 登录阶段（可选）
│   ├── 检测登录窗口

│
├── 操作阶段
│   ├── 菜单导航
│   ├── 功能执行

│
└── 结束阶段
    ├── 保存/退出
    └── 资源清理
```

**配置化描述：**

```yaml
desktop_software_pattern:
  name: "桌面软件操作模式"
  
  phases:
    startup:
      steps:
        - action: "check_process"
          process_name: "${software.process_name}"
          expect: "not_running"
          
        - action: "start_program"
          program_path: "${software.executable_path}"
          wait_time: "${software.startup_delay}"
          
        - action: "wait_for_window"
          window_identifier: "${software.main_window_image}"
          timeout: 30
          
    login:
      condition: "${software.require_login}"
      steps:
        - action: "wait_for_image"
          image: "${software.login_window_image}"
          
        - action: "input_text"
          target: "${software.username_field_image}"
          text: "${credentials.username}"
          
        - action: "input_text"
          target: "${software.password_field_image}"
          text: "${credentials.password}"
          
        - action: "click_image"
          target: "${software.login_button_image}"
          
        - action: "wait_for_image"
          image: "${software.main_interface_image}"
          
    operation:
      steps: "${workflow.steps}"
      
    cleanup:
      steps:
        - action: "click_image"
          target: "${software.exit_button_image}"
          
        - action: "confirm_dialog"
          if_exists: "${software.confirm_dialog_image}"
          action: "confirm"
```

#### 3.2.2 技能配置示例

**示例：通用登录技能**

```yaml
skill:
  metadata:
    name: "universal_login"
    version: "1.0.0"
    description: "通用登录技能，支持多种软件和Web应用的登录"
    
  dependencies:
    operations:
      - "wait_for_image"
      - "click_image"
      - "input_text"
      - "wait_for_element"
      - "click_element"
      
  parameters:
    required:
      - "target_type"
      - "credentials"
      
    optional:
      login_type:
        type: "string"
        default: "auto"
        description: "登录类型：auto/username_password/sso"
        
      timeout:
        type: "int"
        default: 30
        description: "登录超时时间（秒）"
        
  execution:
    pre_check:
      - action: "validate_credentials"
        params:
          credentials: "${credentials}"
          
    main_flow:
      - action: "detect_login_interface"
        params:
          type: "${target_type}"
          
      - action: "fill_credentials"
        params:
          username: "${credentials.username}"
          password: "${credentials.password}"
          
      - action: "submit_login"
        
      - action: "verify_login_success"
        params:
          timeout: "${timeout}"
          
    post_check:
      - action: "capture_state"
        params:
          save_path: "${paths.logs}/login_state.png"
          
  error_handling:
    retry:
      max_attempts: 3
      delay: 5
      
    fallback:
      - action: "try_alternative_login"
        condition: "login_failed"
        
      - action: "send_alert"
        condition: "all_attempts_failed"
```

### 3.3 工作流引擎设计

#### 3.3.1 工作流定义规范

```yaml
workflow:
  name: "工作流名称"
  description: "工作流描述"
  
  variables:
    var_name: "默认值"
    
  triggers:
    - type: "schedule"
      cron: "0 9 * * *"
      
    - type: "event"
      event_name: "file_created"
      
  steps:
    - id: "step_1"
      name: "步骤名称"
      skill: "技能名称"
      params:
        param1: "${变量}"
        param2: "固定值"
      condition: "${条件表达式}"
      on_success: "step_2"
      on_failure: "error_handler"
      
    - id: "step_2"
      name: "下一步骤"
      skill: "另一个技能"
      params:
        input: "${step_1.output}"
        
    - id: "error_handler"
      name: "错误处理"
      skill: "notification_skill"
      params:
        message: "执行失败: ${error.message}"
        
  outputs:
    result: "${step_2.output}"
    status: "completed"
```

## 九、总结

本方案的核心价值在于通过**三层泛化**实现真正的功能通用化：

1. **操作层泛化**：将具体操作抽象为原子能力，通过统一接口调用
2. **流程层泛化**：将业务流程抽象为可配置的工作流，通过配置驱动
3. **决策层泛化**：将人工决策抽象为智能判断，通过LLM赋能

通过这种分层泛化设计，系统可以：
- 快速适配新软件和新场景
- 减少重复代码开发
- 提高系统可维护性
- 实现智能化自动化
